## 一个很强的 AI。又在另一个窗口里。

你正做到一半。问题冒了出来。你知道 AI 也许帮得上忙。

于是你放下手里的事。打开聊天窗口。搬截图。解释背景。再把答案搬回来。忙了半天才发现：自己成了 AI 的搬运工。

与此同时其他东西倒是很擅长主动找你。消息来了。信息流没停。又一个应用郑重其事地告诉你一件无关紧要的事。

**Ling 从一个简单的问题开始：如果那群东西里有一个真的站在你这边呢？**

不是又一个要你耗掉一整天的目的地。而是伸手可及的东西。它帮你读懂一块屏幕。帮你留住一个念头。帮你把任务交给 agent。有时你叫它。有时它先一步介入。

## 是的。它就是打算打断你。

“打扰”通常是句抱怨。在这里它是刻意的设计选择。

悬浮球待在手边。词卡可以主动出现。专注功能试着打断一次走神。免得回过神来才发现整个晚上已经过去了。

想法是 **替你争取注意力。让你把它拿回来。** 不是替 Ling 再赢下一小时的停留时长。

这里有个明显的坑。一个会打断你的工具也可能变成问题的一部分。所以打断是手段而不是目的。重点是把选择权放回你手里。它并不承诺治好分心。

而且注意力只是起点。Ling 不打算认定你整个人生现在都该变成学习时段。你可能在读书。可能在做事。可能在跟人聊天。可能在想下一步干什么。有用的那部分应该跟着你进入当下的情境。而不是把情境硬塞进一个预设分类。

## AI 的最后一公里

模型知道很多。可它未必就在手边。Agent 会规划任务。却未必接得上你的手机和个人知识。

Ling 想弥合的就是这个缺口。

**给你一个随手可用的入口。给 Agent 一组受控的工具。把设备和你想留下的知识接起来。**

这就是产品方向。一个更有能力的日常伙伴。而不是一个被狭窄定义的单一工具。当前实现有边界。下面会照实列出。不会假装方向已经是终点。

## 给 agent 一条通路

你不必把 Ling 当成唯一的 AI 助手。它也可以为你已经在用的 agent 提供工具。

桌面客户端内含一个本地 **Model Context Protocol 服务端**。支持 MCP 的客户端可以请求记忆与知识卡相关的工具。其他工具覆盖复习上下文与提醒 还能保存讲义。配对的 Android 手机还会多出一条通往受支持手机操作的路径。

- **给你的 agent：** 搜索或添加记忆。搜索或创建卡片。取回复习上下文。保存讲义。
- **给你的手机：** 通过可选的手机连接请求屏幕读取 或打开一个被允许的应用。手机屏幕读取返回文字 而不是把原始截图转给外部 agent。
- **给你的控制权：** token 认证与权限范围。敏感的手机操作需要在手机上批准。这不是无限制的远程控制。

MCP 服务在桌面上只绑定回环地址。需要该传输方式的客户端可以用附带的 **stdio 桥**。在桌面设置里启用 并使用生成的连接配置。请保管好 token。

**Hermes 或其他 agent 呢？** 对接点是 MCP 而不是某个厂商专用集成。如果你的 agent 配置支持所需的 MCP 传输与认证 那就是值得评估的接口。本仓库没有专门的 Hermes 适配器。Hermes 兼容性尚未测试。

MCP 与手机连接这两条路径在源码中存在。它们尚未完成本版本的端到端验收。

## 三个平台。一台手机与一台电脑可以对话。

Ling 有 Android 客户端 以及 macOS 和 Windows 共用的桌面代码库。Android 与桌面之间有两条不同的连接方式：

- **局域网同步：** 在私有网络上手工交换知识卡与收藏的答案历史。传输使用 AES-256-GCM。这是快照式交换 不是持续的云端同步。
- **Phone Link：** 把 Android 手机与桌面显式配对。持久连接让桌面 MCP 工具能够触达受支持的手机能力。可用操作取决于手机权限与确认。

这些是 **Android 与桌面之间的连接**。它们不会在手机与两台电脑之间形成自动的三方网状互联。两条路径都尚未完成本版本的端到端验收。Windows 构建还没有在 Windows 机器上运行过。

## 留住你已经在用的工具

### Android 上对 Obsidian 友好的 Markdown

你的笔记不必成为某个应用的永久居民。

Android 笔记使用 **带 YAML frontmatter 的 Markdown 文件**。支持 Obsidian 风格的短路径 `[[wiki links]]`。文件夹导入与导出走 Android 系统文件选择器。这给了你一条把纯文件接入既有 Markdown 工作流的路径。

这就是 Ling 说对 Obsidian 友好的意思。它 **不是 Obsidian 插件**。它不提供实时仓库同步 也不承诺与每一个插件和附件约定完全往返兼容。桌面客户端目前没有笔记界面。这个工作流尚未完成本版本的端到端验收。

### 带一副 Anki 牌组来。接着学。

Android 有真正可用的 **Anki `.apkg` 导入界面**。解析器能处理带 zstd 压缩的 `collection.anki21b` 包 也能处理更早的 collection 格式。导入的卡片使用 Ling 自己的 FSRS 复习进度。Anki 的复习历史不会导入。

桌面源码里有 `.apkg` 解析器 但 **没有导入界面**。它的解析器不支持 `collection.anki21b`。没有 AnkiWeb 同步。Android 导入尚未完成本版本的端到端验收。

Ling 也让你把有用的回答存成知识卡。重点不是永远收集答案。而是留一条回到某些值得记住的东西的路。

## 手边还有什么？

| 能力 | Android | 桌面 |
| --- | --- | --- |
| 屏幕提问 | 屏幕识别与提问 支持追问 | 双击悬浮球截图 并在流式答案面板中回答 |
| 翻译 | 使用你配置的服务翻译 | 通过 AI 或 DeepL 或百度做选中文本翻译 |
| 知识与复习 | 知识卡配 FSRS 以及五套词汇集 | 把答案存成卡片并用 FSRS 复习 |
| 记录 | 聊天历史与带任务和提醒的 Markdown 笔记 | 带收藏与缓存的答案历史。没有笔记界面 |
| 语音 | 实时转写与语音对话 | 通过麦克风或系统音频或混合输入的转写与语音对话 |
| 专注与陪伴 | 专注功能与陪伴气泡 | 陪伴气泡与基于 macOS 前台应用的专注功能 |

云端转写使用豆包或阿里云。语音对话使用腾讯云语音识别 然后交给你配置的模型 最后用腾讯云语音合成。这些都需要单独的凭据。只配一个模型 API key 并不能解锁全部服务。

Windows 没有基于 macOS 前台应用的专注能力。云端语音质量与上述进阶路径尚未完成本版本的端到端验收。

## 开始使用

1. **安装对应的归档。** Android 用 APK。macOS 上解压 ZIP 后打开 `Ling.app`。Windows 上解压 ZIP 后打开 `Ling.exe` 并记住上面未经验证的运行时状态。
2. **带上你的模型。** 在设置里填入 OpenAI 兼容的 Base URL 模型名与 API key。检查连接然后保存。屏幕提问需要接受图像的模型。
3. **为需要的功能授权。** 截屏和悬浮层等能力依赖相应的平台权限。如果 macOS 拦截了应用。请先确认来源与校验值。再到「系统设置 → 隐私与安全性」选择「仍要打开」。
4. **先试试眼前已经有的东西。** 问屏幕上的内容。继续追问。留下有用的部分。agent 连接与手机配对是可选的下一步 而不是前置条件。

Ling 不附带服务凭据或模型额度。配置缺失时不会悄悄切到内置的模型服务。更新默认没有配置官方来源。

**隐私与花费：** 配置的服务可能根据功能收到截图 或选中文本 或音频。服务商可能对请求收费。请使用你信任的端点 并在发送敏感内容前查看它们的政策。

## 从源码构建

```bash
git clone https://github.com/Nirxzzz/Ling.git
cd Ling
```

### 桌面

使用 **Node.js 24+** 与 npm。首次安装与打包需要联网下载 Electron。

```bash
cd desktop
npm ci
npm start
```

运行 `npm test` 跑现有测试。用 `npm run pack:mac` 或 `npm run pack:win` 打 ZIP 包。

[桌面开发指南](desktop/README.md)

### Android

使用 **JDK 17 + 系统 Gradle 8.14 + Android SDK 35**。先配置本地 SDK 路径。本仓库不包含 Gradle wrapper。

```bash
cd android
gradle testDebugUnitTest assembleDebug
```

APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。调试构建不需要私有签名材料。发布构建需要你自己的 keystore。缺失时会明确失败。不会退回调试签名。

[Android 开发与签名指南](android/README.md)

两个客户端都不承诺逐字节可复现的构建。Android 没有依赖锁定或校验配置。桌面锁定了 npm 依赖 但运行时下载与归档元数据仍会影响输出字节。

## 几个值得知道的边界

- **独立身份：** Android 使用 `com.chun.lingzhu.opensource`。桌面使用 `com.ling.opensource` 默认数据目录为 `ling-opensource`。这些构建不会替换原来的官方安装。
- **没有自动更新安装器：** 桌面更新只下载 ZIP 并在文件管理器中显示该文件。默认没有启用更新源。
- **没有 iOS 构建：** 这里没有 iOS 工程或 IPA。macOS 打包面向 Apple Silicon 而不是 Intel Mac。
- **模型回答可能不完整：** 桌面流式输出不会单独标注 `finish_reason=length`。重要结论请自行核实。
- **语音不保证无回声：** 系统回声消除与软件检查还没有在真实设备上验证。
- **桌面安全需要小心：** 渲染进程沙箱已关闭 也没有设置 CSP。preload 暴露了较宽的 IPC 面。只加载随包提供的本地页面。公开源码不等于完成的安全审计。
